# localenvx

A local encrypted .env manager.

## Usage

Run `localenvx --help` for runtime options and `localenvx manage --help` for management commands. Options belong to each command: `localenvx manage get --help` shows only get options.

```bash
# Load .env, decrypt its values, and run your command.
localenvx -- node app.js
# Do the same with the explicit run command.
localenvx run -- node app.js
# Load multiple files (.env.local takes priority over .env).
localenvx -e .env.local -e .env -- node app.js
# Load development files, starting with .env.development.local.
localenvx -c development -- node app.js
# Set a temporary value for this command only.
localenvx -v TEMP_NUM=4000 -- node app.js
# Preview file selection without loading files or running the command.
localenvx --debug -- node app.js
```

For first-time setup, run `init` before running your app:

```bash
# Generate a random key in the local credential file.
localenvx manage init
# Check credentials and .env status without revealing values.
localenvx manage status
# List key names and encryption status across all .env files in this directory.
localenvx manage ls --all
# Save an encrypted secret in .env.
localenvx manage set API_TOKEN example-secret --enc -y
# Open the local web UI to view and edit environment variables.
localenvx manage ui
```


### How the .env looks like

```dotenv
# Secret values are stored as ciphertext (shortened here).
API_TOKEN=encrypted:v1:BHe9lUzNq4oS0tX...

# Use @PLAIN to keep the immediately following value readable.
# @PLAIN
PORT=3000
```

### How encryption and decryption work

`set --enc` turns your secret into ciphertext before saving it to `.env`.
When you run a command, localenvx uses your local credentials to decrypt the value
and passes it to your app as a normal environment variable. Your app sees the
original secret; `.env` stays encrypted. Everything happens on your machine.

Back up the credential file generated by `manage init`: it contains the encryption key. No password is required. `init` never overwrites an existing credential file. Use `localenvx manage init --project` to create `.localenvx/config.toml` in the current directory instead of the user config.

### Why encrypt .env if it can be decrypted locally?

Yes, anyone with your credential file can decrypt the values locally. 

The purpose is to reduce exposure when `.env` contents are copied or leaked without the credential file. For example:

- Software that collects repository files may capture encrypted values instead of plaintext secrets.
- Files sent to an AI service may be retained and exposed in a later breach; encrypted values remain unreadable without the key.

This protection depends on keeping the credential file separate from the exposed files.
